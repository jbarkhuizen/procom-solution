## How the business logic works (read before changing)

- **Money is integer cents** everywhere (`*_cents`). Weights in grams.
- **Pricing** (`server/pricing.js`): `retail = max(cost_excl_VAT × 1.15 × (1 + markup), cost × 1.15 + minimum profit)`, rounded **up** to the next rand (`roundRetail`). Minimum profit per item = Site setting `minProfitRand` (**R10**, owner 2026-09-30) so cheap items cover the Payfast fee. Business is **not VAT-registered** (supplier VAT is a cost). Markup precedence: product → nearest category up the tree → site default (**10%**). `price_mode='manual'` products are never repriced.
- **Storefront reads the catalogue live** from the API (no publish step, unlike lapanza3d). Empty categories are hidden.
- **Warehouse feed**: upload → `POST /feed/preview` (parse, auto-map columns by heading aliases, cached 30 min by token) → `/feed/preview/map` (live re-map) → `/feed/import`. Mapping is by header *name* so one mapping applies to every sheet. Rows with no code and no price are section headings (become supplier category) or notes. No brand column → real sheet name, else a first word covering ≥40% of names.
  - `completeList` = true: listed products missing from the file go out of stock (never auto back in stock). **Flyers/partial lists** (PDF flyer mode defaults off) only update the **cost** of known items.
  - Re-import updates costs and reprices auto-priced listed products.
  - `deleteImport` removes the history row + feed items whose latest data came from that file, **except** items listed in the shop or touched by a newer import.
  - **SMD auto-list** (`server/smd-rules.js` + `server/smd-autolist.js`; Warehouse feed → "Auto-list SMD Infant Essential…" / "Auto-list SMD Cash Wholesale…"): rules match SMD's category column, the brand tab and/or the product name (first match wins — order matters) and put each row from the latest import of that list (file name `*infant*` / `*cash*wholesale*`) into a store sub-category. A preview panel shows counts per category, **categories that would be created** (spot near-duplicates of live names here), skipped rows with reasons and unrecognised rows. Then it creates missing categories by name (parents must match live names exactly), lists at default markup, live; never overrides an admin-set category; re-running only lists new items. Always skipped: cost under R1 or over R100,000 (SMD typos), plus per-list `skip` rules (Cash: display stands, junk rows, refurbished/consumables, the Creality tab). A rule with `quote: true` creates its category with delivery quoted (Cash: Gaming › Gaming Chairs & Desks); `markup: N` creates it with its own markup (Cash: Phones and Laptops & Tablets pinned at 10%). A list's `heavy` pattern marks individual products delivery quoted when listed (Cash: soundbars/subwoofers, big party speakers, 24"/27" monitors, projector screens, heavy-duty or 86"+ TV mounts, racing cockpit, electric scooter — 49 in Sept 2026); products with an admin-set delivery choice are untouched. When changing rules, add a case to `smd-autolist.test.js` and re-run against the real file.
  - `cleanProductName()` strips SMD's "(To Be Ordered in Qty of N)" / "( Order in Qty of N)" from shop titles; `parseMinOrderQty()` reads it into `min_order_qty`.
- **Supplier APIs** (live 2026-09-29, logins/keys in Admin → Suppliers, encrypted by `vault.js`):
  - **Supplier update emails** (Site settings, `supplierReportMode`): `every` = after each run (default), `daily` = one combined email at 19:00 SAST (`server/supplier-digest.js`, env `SUPPLIER_DIGEST_TIME`), `off`. Every run is recorded in `sync_report_runs` (kept 30 days); connection checks are always emailed at once. Report email goes to `supplierReportEmail` ( default lapanzaonline@gmail.com; comma-separated; blank = `ownerNotifyEmail`), with a **Word overview attached** (`server/sync-report.js`: `snapshotPrices` before / `diffPrices` after the sync -> counts + products that went on special and whose shop price came down; `buildSyncReportDocx` via the `docx` package). SMD connection checks get no attachment.
  - **Esquire** (`esquire.js`, 06:00/12:00/18:00 SAST): whole feed imported as a complete list (prices incl VAT → stored excl VAT), auto-list via `esquire-rules.js`, items leaving the feed go out of stock and come back (`products.out_by_feed`).
  - **SMD** (`smd-api.js`, 06:30/12:30/18:30): updates listed SMD products only (cost/specials as Sale via `special_by_feed` + `compare_at_cents`, stock from SOH → `supplier_stock_qty`, blank descriptions, photo queue `product_media_queue`); never categories; new SKUs → Warehouse feed (`smd-api.json`). Owner decision: SMD SOH 0 = out of stock.
  - SMD auto-list (`smd-api-rules.js`, switch `smdApiAutoList`) lists new SMD SKUs each sync; pack size parsed from the name.
  - Storefront shows live supplier stock (`stockOnHand` / `stockLeft`), the SKU, and the warehouse icon (public label only, also when out of stock). The Specials page (`features/specials.js` `productsOnSpecial`) = admin specials + products with `compare_at_cents > price_cents`, with a category quick filter (`?category=slug`, counts per top-level category; `src/js/specials.js`). Shop and Specials use "Load more" (`src/js/load-more.js`), no page numbers. Cards show the SKU; the shop defaults to "In stock only" (`?inStock=0` turns it off). Search (`queryProducts`) also matches names/SKUs with spaces and punctuation removed for terms of 3+ chars (`compactSearch`).
  - **Same product from SMD and Esquire = two separate listings** (owner, final 2026-09-29): each keeps its own price, stock and warehouse icon; never merge them.
  - **Owner rule (2026-09-29): not in the API feed = not listed.** SMD sync / Esquire import hide (`active = 0`, `products.hidden_by_feed = 1`) listed products missing from the API and show them again when they return; products an admin hid are never shown again by a feed; the SMD sync skips hiding when >20% are missing (incomplete response).
  - Both: an admin's manual out-of-stock is never undone; admin-changed photos never replaced (`images_from_feed = 0`); guards skip runs whose data looks truncated.
  - **Report layout** (owner 2026-10-06): the email is short (headline numbers + "Needs your attention" + pointer); the **Word file is the full record** -- attention box, summary with a "last run" column, every changed product grouped by category with admin/shop links, stock out/back with 30-day sales, hidden/shown/new, supplier products not yet in the shop, run details. Attention levels (`ATTENTION` in `sync-report.js`): shop price drop >50%, rise >15% (not when a special just ended), hidden or out-of-stock products that sold in the last 30 days. Connection checks keep the full email. `changes_json` of runs before 2026-10-06 lacks the new lists (the builders tolerate that).
  - **API run log** (Admin -> System -> API run log, `server/api-run-log.js`, table `api_run_log`): written by `esquire.js` / `smd-api.js` after every run (scheduled, manual, SMD check); never breaks a sync; seeded once from `sync_report_runs`.
- **Price drops** (owner 2026-10-07; `server/features/pricedrops.js`, `price-drops.html`, `src/js/price-drops.js`, `admin/pages/price-drops.js`): products whose shop price came down after a sync. **Any** drop in our shop price (supplier cost drop or supplier special) of **>= 5% and >= R10**, kept **7 days** from the latest drop, live **automatically**, **sold-out items stay greyed**. `recordPriceDrops()` runs after every sync (and closes ended drops); the page re-checks the LIVE price on every view, so a drop is gone the moment the price is back at the old price. Settings `priceDropsOn/MinPct/MinRand/Days`. Admin shows supplier cost columns next to my pricing (Payfast fee, profit, floor), Hide/Pin/bulk/CSV. Checkout (`cart.js refreshCart` + `checkout.js`): a price that went UP since the item was added must be confirmed, sold-out items are removed with a notice, "while stock lasts / full refund" disclaimer when the cart holds a drop item (`/api/cart/refresh` returns `priceDrop`). Nothing here changes a price; the engine still prices everything. Mockups: `docs/mockups/`.
- **Pack items** (`min_order_qty` > 1, from SMD's name "( Order in Qty of 12)" -- SMD's API has no pack field): cards/product page show the pack total ("R576.00 per 24", unit price under); **whole packs only** (owner 2026-10-06): +/- step a pack, typed amounts snap to whole packs (`toWholePacks` in `src/js/cart.js`), `createOrder` refuses part packs. The SMD sync keeps listed products' pack size in step with SMD's name (`stats.packSizes`).
- **Delivery quoted** (`quote_delivery`, **store-mode suppliers only**): category flag inherited by sub-categories; product override (NULL inherit / 1 always / 0 never). If a store-mode shipment has an item needing a quote, the **server** offers only quote (or collect), charges R0 delivery, requires a street address and sets `orders.delivery_quote=1`; admin shows a banner with pre-written WhatsApp/email quote. On for: 3D Printers FDM/Resin, Laser Engravers, Furniture, Luggage & Travel, Gaming Chairs & Desks; per product for heavy Cash Wholesale items.
- **Delivery is per supplier** (`server/delivery.js`, Admin → Suppliers → Delivery): each supplier's items are one shipment with its own choice at checkout; mixed carts get one choice per supplier and the fees add up; each supplier gets its own order sheet. A supplier is **flat** (one courier fee per order, free once *their invoice* = our cost × 1.15 reaches a threshold; covers large items, so no delivery quotes) or **store** (store-wide shipping options + delivery quotes; also used for products without a supplier). Either may offer **free collection** (address/hours/what-to-bring). Customers only ever see the supplier's *public label* (e.g. "Edenvale warehouse"), never its name; the collection address appears only at checkout (map loads when Collect is chosen) and in emails. **SMD**: flat **R157** to the customer (R150 SMD charges us + the Payfast fee on it; `suppliers.delivery_cost_cents` = what the courier costs us, used by Financial overview), free from R5,000 invoice incl VAT; collect at 2 Lascelles Road, Meadowbrook, Edenvale, Mon–Fri 09:00–16:00, collector brings the collection notice + ID/driver's licence/passport (anyone with the notice may collect). Admin order → "Ready for collection — email notice" per collect shipment. Orders store the shipments in `orders.fulfilment_json`.
  - **Esquire** ("Samrand warehouse", store mode until its courier fee is known): collection at 71 Landmarks Avenue, Kosmosdaal Ext 11, Samrand (Mon–Fri 09:00–16:00 · Sat 09:00–12:00) and **own courier** (`suppliers.own_courier_enabled`: free, no address needed, customer emails waybill + collection date; order sheet says "customer's own courier").
  - **Courier insurance** (`categories.courier_insurance_pct`, inherited): that % of the item price is added as its own line (shipment `insuranceCents`, included in `shipping_cents`, shown separately in checkout/emails/invoice/admin) when our courier carries it (courier/store/quote) -- never on collect or own courier. Esquire Televisions: 3%.
- **Store-wide shipping options** (store-mode suppliers only, today Esquire): `auto_weight` courier brackets by shipment weight (0–3 kg R157, 3–10 kg R229, 10–25 kg R313 to the customer; `shipping_options.cost_cents` R150/R220/R300 = cost to us); PUDO Locker and Local Delivery are switched off (code dormant). Supplier data has **no weights** (default 1 kg) — that's why large items use delivery quotes.
- **Vendor details** (Admin → Suppliers): address, order process, portal website, portal username/password and supplier API token/key -- secrets encrypted with `server/vault.js` (key: `VAULT_KEY` or the server-created `.vault-key`, never in `data/` or backups), never listed; a portal password is revealed only on click, and each reveal is audit-logged.
- **Feature modules** (`server/features/`, `admin/pages/`; contract in `server/features/README.md`): Phase 1 of the Lapanza3d-style upgrade (2026-09-28).
  - **Accounts** (`accounts.js`): optional customer accounts (register → email verify → login, reset, account page `account.html` with orders/invoices/saved details/newsletter opt-in); guest checkout stays; orders link to the account by email or login session. Admin: Clients (CRM grouped by email), Registered users.
  - **Invoices** (`invoices.js`): sequential `INV-000001` issued when Payfast confirms payment (idempotent, gap-free), emailed; printable `invoice.html?o=<orderId>` ("Invoice", no VAT — not VAT-registered). Admin: Invoice history (CSV, monthly totals, "Issue missing invoices" backfill).
  - **Promos / Specials** (`promos.js`, `specials.js`, shared `discount-common.js`): nothing may go below **cost incl VAT + the Payfast fee** on that price (owner 2026-09-30; `floorContext(db)` = VAT + the dearest enabled Payfast method, fixed part per unit) — specials are floored per unit, promo discounts capped at the margin above that floor across the lines they apply to; admin shows where the cap bites. Specials show as price + struck-through normal price; public `specials.html`. Promo uses count paid orders only.
- **Phase 2 features** (2026-09-28):
  - **Analytics** (`analytics.js`, `src/js/analytics-beacon.js`): first-party only — anonymous visitor id in localStorage, no IPs/cookies/third parties; honours Do Not Track/GPC; bots and admins ignored; raw rows kept 12 months then rolled into daily totals. Funnel reads paid orders from `orders`.
  - **Traffic sources** (owner 2026-10-08; `features/channels.js`, `features/geoip.js`, `sourcesSummary()` in `analytics.js`, Admin -> Analytics): visits are grouped into channels (Google, other search, Facebook, Instagram, WhatsApp, email/newsletter, paid, other sites, direct) from the referrer host and campaign tags (`utm_source/medium/campaign`, which win over the referrer). ## Working conventions / gotchas on this machine

- A security hook rejects any Write/Edit whose text contains the DOM "inner HTML" property name or the word exec directly followed by an opening parenthesis — even in docs. Use `setHtml()` from `src/js/dom.js` / `admin/dom.js` (the single audited HTML sinks — escape every dynamic value with `esc()` / `h()`); for SQLite's multi-statement call write a placeholder and replace it with `sed`.
- Reading `.env*` files is blocked by a permission rule (good — never print secrets; check "set/empty" only).
- Bash heredocs containing apostrophes break in this tool — write scripts to the scratchpad and run them.
- Playwright MCP can only save screenshots under the project (`.playwright-mcp/`, gitignored) — delete after use. The Claude Browser `preview_start` doesn't find this project's launch config; start servers with background Bash instead.
- Vite proxy must keep `changeOrigin: false` (otherwise admin saves fail the same-origin check in dev).
- Owner preferences: plain-language explanations; **propose category structures as a table for approval before creating them**; confirm before outward-facing actions; commit with the Co-Authored-By trailer.
